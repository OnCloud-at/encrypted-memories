# Support and Feedback

## Questions

Do not open a GitHub Issue for setup or usage questions. Use the [[Quick Start|Quick-Start]], the guide for the relevant screen, and [[Troubleshooting|Troubleshooting]].

There is no separate public Q&A channel. The Wiki is the how-to channel.

If the Wiki is missing a necessary explanation, propose the exact documentation improvement as a feature request rather than posting an open-ended question.

## Reproducible bugs

Use the repository’s structured Bug Report form only when you can describe a reproducible problem. Include:

- Platform and exact device model
- OS version
- App version and build from Settings
- Short reproduction steps
- Expected and actual result
- Frequency and impact

The in-app bug report screen can export a support report. Review it before attaching it.

Never include passwords, API keys, private links, session data, or private photo content.

## Feature proposals

Use the structured Feature Request form for one concrete outcome. Explain the problem, the smallest useful result, affected platforms, and current workaround.

Search open and closed issues before submitting either form.
