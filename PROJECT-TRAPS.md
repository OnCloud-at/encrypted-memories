# Project traps

Hard constraints from known first-attempt failures. Read before changing code.

- Never route a shared-with-me album into the HTTP album writes (`AlbumsRepository.addPhotos/removePhotos/setAlbumCover/deleteAlbum`, `ProtonAlbumWriteService`, `DriveSDKBridge.setAlbumCover/deleteAlbum/removePhotos`), and never enable editor/admin writes from the SDK role alone. Why: these writes take a bare `AlbumID` and resolve the account's own Photos share, volume and root key (`resolveRootMaterial`, `resolveAlbumMaterial`, `resolvePhotosRoot`), so a foreign-volume album cannot be addressed; a local 2xx is not proof of shared-album support. Keep `AlbumCapabilities.canWriteSharedAlbums == false` until a volume-qualified, authenticated-runtime-verified transport exists. Files: `Packages/EncryptedMemoriesKit/Sources/ProtonDriveBackend/Albums/ProtonAlbumWriteService.swift`, `Packages/EncryptedMemoriesKit/Sources/AlbumCore/AlbumsRepository.swift`.
- Allow-list every intentionally public Markdown file in both `.gitignore` and `scripts/check-public-tree.sh`. Why: changing only `.gitignore` makes the file trackable, but CI still rejects it as a private Markdown path. Files: `.gitignore`, `scripts/check-public-tree.sh`.
- Keep candidate disposition separate from review coverage. PR #51 completed successfully on reviewer commit `571a1010`, but one generic branch in `.github/scripts/review_evidence.py` mapped low confidence, existing issues, missing context and invalid source quotations to the same grey result. Record reason counts without model text; discard ordinary suspicions, identify real missing context, and regenerate invalid evidence. Keep optional test-strength notes separate from verified coverage gaps, or a complete review is incorrectly reported as incomplete. The old run did not retain enough diagnostics to identify which condition occurred.
- Host `MobilePhotoViewer` in hosted iPad tests through the production route (`MobileViewerRouter` -> `.fullScreenCover(item:)`) with a non-animated presentation; never as a direct `UIWindow` root. Why: the native `.inspector` bridge (`UIKitInspectorSplitViewController`) books the content column's 360 pt trailing inset per column transition. A directly hosted viewer resized via `window.frame` plus trait overrides collapses correctly but keeps the 360 pt inset whenever the main thread is contended (a preceding test's account teardown, or synthetic 80/20 ms main-actor bursts); an animated cover on iPadOS 27 never applies the inset initially (pager 1032). Both states are permanent, not delayed; production `additionalSafeAreaInsets` stays 0, so no production layout fix exists for them. Files: `iOSTests/MobileViewerInspectorTests.swift`, `iOSApp/MobilePhotoViewer.swift`. Evidence: `/Users/thomas/Developer/xcode/EncryptedMemories/Logs/inspector-architecture-2026-09-15/`.
- Keep proactive background cache reduction separate from observed memory pressure in admission, lease checks and recovery hysteresis. Mapping background activity to a warning blocked automatic backup and ML even during an allowed execution window. Real pressure must still update the runtime when the cache tier stays unchanged. Files: `LibraryRuntimeAppleAdapter/AppleLibraryRuntimeAdapter.swift`, `PhotosCore/MemoryPressureGovernor.swift`, `PhotosCore/LibraryResourceCoordinator.swift` under `Packages/EncryptedMemoriesKit/Sources`.
- Use the composite cursor as an index range in ML vector pagination. The equivalent `volume_id > ? OR (volume_id = ? AND node_id > ?)` scanned earlier rows on Apple SQLite 3.51.0 despite `LIMIT` and keyset ordering. Preserve the non-null `(volume_id, node_id)` order, epoch filters, corrupt-row advancement and page boundaries. File: `Packages/EncryptedMemoriesKit/Sources/MLSearchCore/SQLiteMLIndexStore.swift`.
- Inspect SDK bootstrap cleanup before restoring a new worktree's dependency. `scripts/update-proton-sdk.sh` deletes the shared build caches after applying patches. Restore the exact pinned SDK and reviewed patches without that cleanup when only the new worktree needs its missing checkout; do not reset an existing dirty SDK or bypass the shared build lock.
- Distinguish successful end-of-stream from storage failure before claiming complete ML search results. The former nonthrowing `MLIndexStore.forEachVectorBlock` stopped on any non-row SQLite result, so prepare or step failures appeared as successful empty or partial searches. Keep its throwing contract through the search engine, and discard accumulated results after failure. Logging alone cannot correct the result. Files: `MLSearchCore/MLIndexStore.swift`, `MLSearchCore/SQLiteMLIndexStore.swift`, `MLSearchCore/MLSemanticSearchEngine.swift` under `Packages/EncryptedMemoriesKit/Sources`.
- Wait for both scene IDs in the activity ledger before asserting multiwindow registration. A rendered grid can precede the asynchronous scene callbacks, producing a count of one for two windows. This wait fixes the registration assertion; it does not fix inspector adaptation. File: `iOSTests/MobileSignedInMultiwindowTests.swift`.
- Authorize explicit thumbnail reads from the graph's thumbnail retention scope (accessible thumbnail identities plus their burst members), not primary-library inclusion or the analysis scope. Burst members are not library items; authorizing from the analysis scope left every series filmstrip empty although the library thumbnails were fully cached. Shared albums remain excluded from the primary library, but their foreground disk, network and decoded-cache paths need read access. Keep epoch, session, revision and revocation fences; background analysis must not populate the grid LRU. Using the selected scope made shared tiles black while covers and full photos worked. File: `Packages/EncryptedMemoriesKit/Sources/MediaFeedCore/ThumbnailFeedCore.swift`.
- Load photo information with the full SDK `(volumeID, nodeID)` and resolve album titles against both owned and shared catalogs. The former metadata path dropped the volume and used the account's own Photos share key chain; the title lookup ignored shared albums. Decode optional SDK metadata sections independently, and distinguish absent metadata from request failure. Files: `Packages/EncryptedMemoriesKit/Sources/ProtonDriveBackend/SDKPhotoMetadataReader.swift`, `Packages/EncryptedMemoriesKit/Sources/AlbumCore/AlbumsRepository.swift`, `Packages/EncryptedMemoriesKit/Sources/PhotoViewerCore/ViewerTitleMetadataCoordinator.swift`.
- Before adding `.navigationTitle(` to any file in `iOSApp/`, or naming a helper so that a call site contains the substring `.navigationTitle(`, read `ProjectHygieneTests.testMobileRoutesUseConsistentNativeTitles`. It substring-scans every Swift file in `iOSApp/` (not only marked blocks); `MobileRootChrome.swift` and `MobilePhotoViewer.swift` are the only exempt files, and the exemption for the viewer asserts exactly one `.navigationTitle(viewerTitle.line1)` plus `.navigationSubtitle(viewerTitle.line2)`. A grid-route title helper was renamed to `barTitle(default:)` for this reason. Files: `Packages/EncryptedMemoriesKit/Tests/UploadFeatureTests/ProjectHygieneTests.swift`, `iOSApp/MobileSelectionToolbar.swift`.
- Record progress callbacks synchronously under a lock in tests. An unawaited task per callback can reorder actor work and create false monotonicity failures. File: `Packages/EncryptedMemoriesKit/Tests/PhotosCoreTests/DragOutTests.swift`.
- Mount SwiftUI `ToolbarOverflowMenu` only while it has content, and detect it in hosted tests through `UINavigationItem.additionalOverflowItems != nil`, never through a localized "More" label. Why: the menu fills `additionalOverflowItems`, and UIKit shows the ellipsis whenever that property is set, even for an empty menu; an always-mounted empty menu put a dead ellipsis beside Select and truncated the library title on iOS 27. A label oracle passed that defect on a German simulator and failed the correct selection state. Files: `iOSApp/MobileTimelineScreen.swift`, `iOSTests/MobileTimelineChromeTests.swift`.
- Apply the app's brand tint outside the Settings sheet and viewer cover in `MobileMainTabView`, and keep `.tint(nil)` on the viewer's bar stack. Why: a tint set only on the inner `TabView` does not reach `.sheet`/`.fullScreenCover` content; with the Xcode 27.0 SDK the Settings icons fell back to system blue although TestFlight Beta 14 (Xcode 27 Beta 6, Release) showed purple. Without `.tint(nil)` the native viewer bar icons turn purple. Compare tint through the production app root, never a directly hosted screen, which is blue by construction. Files: `iOSApp/EncryptedMemoriesMobileApp.swift`, `iOSApp/MobilePhotoViewer.swift`, `Packages/EncryptedMemoriesKit/Tests/UploadFeatureTests/ProjectHygieneTests.swift`.
- Judge Simulator capture smoothness only by frame gaps during visible motion, never by raw VFR gap counts. Why: `simctl io recordVideo` writes no frames while the image is static, so most gaps of 40 ms or more are harmless. The motion-only count separated stuttering automated takes (12 motion gaps in `iphone-metal-grid-native.mov`) from nearly clean owner takes (1 in `iphone-owner-native-120.mov`). Method: ffmpeg `tblend=all_mode=difference,signalstats` YAVG > 0.8 next to a gap. Files: `Marketing/Captures/Video/` and `Marketing/Capture/analyze-motion-gaps.sh` (local, ignored).
- Block Smart Search intents only while a Visual Search removal is running (`visualRemovalsInFlight > 0`), never merely because a `.disableVisualSearch` journal is pending. Why: a stalled journal after a storage failure, an offline start or a catalog refresh had no reachable path to finish. Settings hid Retry behind native indexing status, and the pending journal also stops native indexing. Enable, select, catalog refresh, `retry()` and `start()` must finish a stalled journal, and only one completion may run. File: `Packages/EncryptedMemoriesKit/Sources/MLSearchCore/MLSmartSearchLifecycle.swift`.
- Run `MLSearchCoreTests` with `swift test --no-parallel` before judging lifecycle failures. Why: about 21 `MLSmartSearchLifecycleTests` hit their 10-second `waitUntil` limits under parallel execution, identically on an unmodified base, while serial runs pass. File: `Packages/EncryptedMemoriesKit/Tests/MLSearchCoreTests/MLSmartSearchLifecycleTests.swift`.
- Call Liquid Glass natively (`glassEffect(in:)`, `buttonStyle(.glass)`, `buttonStyle(.glassProminent)`). The `protonGlass` wrapper in `DesignSystemCore/AdaptiveGlass.swift` and its centralization guard are gone (PR #58): both platforms require version 26, so the availability fallback was dead code. A branch created before that merge still calls the wrapper and stops compiling after a rebase; convert those call sites. Files: `iOSApp/`, `App/`, `Packages/EncryptedMemoriesKit/Sources/PhotoViewerFeature/PhotoViewerView.swift`.
- Edit `Localizable.xcstrings` as text, never by reloading and dumping the JSON. Why: the catalog mixes one-line and expanded `stringUnit` blocks, so `json.dump` reformats about 10,000 lines and buries the real change. Insert the new key next to its neighbours and validate with `json.load` afterwards. File: `Packages/EncryptedMemoriesKit/Sources/PhotosCore/Resources/Localizable.xcstrings`.
- Resolve the iOS test simulator from the installed devices, never by a pinned name. The GitHub image `xcode-27-arm64/20260912.0186` ships iPhone 17, 17e, 18 Pro, 18 Pro Max and Air for iOS 27.0; Apple dropped the previous Pro models, so `name=iPhone 17 Pro` failed before any test ran. That image also installs only Xcode 27.0 Release Candidate (build 27A266a) and symlinks `/Applications/Xcode.app` to it, so compare build numbers, not app paths, before blaming a toolchain difference. File: `scripts/verify-ios-app-tests.sh`.
- Reproduce a failing `MLSmartSearchLifecycleTests` wait with `LIBDISPATCH_COOPERATIVE_POOL_STRICT=1 swift test --filter MLSearchCoreTests.MLSmartSearchLifecycleTests --no-parallel` before blaming the branch under test. Smart Search indexing makes no progress while the cooperative pool has no spare thread, so the waits expire even for a single asset; on a busy CI runner this appears as a random red `Swift package tests`, and a job re-run passes. A longer poll interval does not help, and the root cause in the indexing path is still open. Files: `Packages/EncryptedMemoriesKit/Tests/MLSearchCoreTests/MLSmartSearchLifecycleTests.swift`, `Packages/EncryptedMemoriesKit/Sources/MLSearchCore/MLIndexRunner.swift`.
