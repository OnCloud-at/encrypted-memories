# Repository constraints

- Bound suggestion qualification by the query result limit. Keep the six-match floor. A coverage-scaled threshold above 400 rejected every concept in libraries above 100,000 indexed assets. See `MLSearchConceptDiscovery.swift`.
- Check refresh ownership before publishing any asynchronous result. Cancellation alone does not reject an older overlapping call. Propagate cancellation to detached workers. See `SmartSearchDiscoveryModel.swift`.
- Distinguish failed visual queries from successful empty results. A failed sensitive gate must suppress previews and remain retryable. Never finalize visual completion from failure. See `SmartSearchDiscoveryModel.swift` and `MLSearchConceptDiscovery.swift`.
- Preserve interactive search while automatic work yields. Resource leases can report active user interaction even for an admitted interactive request. Apply suggestion preemption without cancelling the user's own query. See `MLSmartSearchLifecycle.swift` and `LibraryResourceCoordinator.swift`.
- Use `scripts/build-paths.sh` and its build lock for every SwiftPM/Xcode gate. Do not create per-worktree caches or remove another build's lock. Vendor SDK sources must match the pinned commit, client rename, and both versioned patches before testing.
- Source `scripts/build-paths.sh` from Bash, not zsh, and stop immediately when lock acquisition fails. In zsh, the `EXIT` trap installed inside `encryptedmemories_acquire_build_lock` runs when that function returns, removing the shared lock before the build starts. The same trap lasts until shell exit in Bash. Prefer the repository's Bash verification scripts; direct test commands must explicitly select Bash. This affects concurrent worktrees using the canonical build root.
- Do not infer the library size from the indexed count. A lower count can mean unfinished indexing. Only an authoritative inventory permits reconciliation. Preserve the guarded coverage update in `MLSmartSearchLifecycle.swift`.
- Close each streaming owner explicitly; do not rely on loader deinit to cancel tasks that retain the loader. Individual AVFoundation request cancellation must preserve shared prefetch. Never close another player's account admission gate. See `VideoStreaming.swift`, `ProtonVideoResourceLoader.swift`, and `VideoPrefetchCompletion.swift`.
- Promote a demanded prefetch through its original governor priority handle. Swift task priority does not change the governor queue. Preserve the demand-scoped upload suspension and one fetch per block. See `ProtonRequestGovernor.swift` and `PhotoVideoStreamSource.swift`.
- Renew a persistent view's activity after a runtime generation reset. An old registration must neither block new activity nor end another owner's activity. See `LibraryRuntimeState.swift` and the search hosts.
- Accept zero-only XAttr sizes beyond actual revision blocks. Proton's legacy web writer appends a zero remainder for exact chunk multiples and empty files. Strict count equality rejects valid uploads. Reject missing or nonzero unmatched sizes; preserve oversized decrypted-block prefix compatibility. See `PhotoVideoStreamSource.swift` and its regression tests.
- Claim one per-block encrypted fetch atomically before cache lookup. Demand can arrive before prefetch registration; observing only the prefetch dictionary produced 20 HTTP fetches for 20 concurrent requests. Preserve a continuous demand priority scope across failed-prefetch retry. See `ProtonVideoResourceLoader.swift`.
- Fence cache publication inside the disk write with the player owner. An account cache generation alone does not reject a queued write after player close. Finish pending AV loading requests once on owner close; AV cancellation owns its own terminal result. See `VideoByteRangeCache.swift`, `VideoCacheWriteOwner.swift`, and `VideoLoadingRequestCompletion.swift`.
- Give every iOS export and support report its own UUID directory. Per-operation cleanup must never delete the shared ShareExports root or another operation's files. Preserve cold-launch cleanup. See `MobileSelectionSupport.swift` and `MobileShareExportTests.swift`.
- Preserve native video transport control unless real-device tests establish an equivalent intent contract. Custom resume logic can override native pause, replay, Picture in Picture, or audio interruptions. Keep automatic waiting and current buffer sizes; readiness must not issue play commands. See `VideoPlaybackController.swift` and `MobilePhotoViewer.swift`.
- Accept both CoreDevice UUIDs and physical device identifiers when selecting a local installation target. Connected WLAN devices can report `connected`, not an `available` prefix. Match the exact device name and physical reality. See `scripts/rebuild.sh`.
- Keep share-file ownership alive across payload copies and partial-share promotion. A dismissed export controller must not be retained across the download; its cancelled task still owns cleanup until the backend returns. Keep active share files until native dismissal completes. See `MobileSelectionSupport.swift`.
- Update existing accessibility elements when selection changes. Rebuilding only on viewport movement leaves VoiceOver's selected state stale after a press; replacing focused elements is unnecessary. See `MetalGridAccessibilityProvider.swift`.
- Keep the required `PROJECT-TRAPS.md` exception explicit in both `.gitignore` and `scripts/check-public-tree.sh`. Allowing the file in Git alone still fails repository hygiene. Do not allow private audit reports or broader Markdown patterns.
- Only the active timeline tab may join the launch-banner matched-geometry group. iPad keeps Library and Search tabs mounted in one namespace; both previously advertised a source and SwiftUI reported undefined geometry. Preserve the loading-cover handoff and inactive-tab state. See `LibraryActivityBanner.swift` and `MobileTimelineScreen.swift`.
- Clean up fixture-created scenes even when a hosted test throws. Reactivate the original scene and choose a foreground-active scene for window anchors. Programmatic iPadOS 27 tab selection can leave native search inactive; activate the real scene-owned search controller and still require its attached field. Do not change production search layout to satisfy synthetic tab selection. See `MobileSignedInMultiwindowTests.swift` and `MobileSceneOwnershipTests.swift`.
- Separate wireless installation from application launch. A locked, paired iPad can accept the signed app and report its installed version over WLAN, while SpringBoard rejects launch with `Locked`, including `--no-activate`. Keep the passcode and Auto-Lock unchanged; request a temporary unlock for runtime acceptance. Include default apps when verifying the installed bundle with Xcode 27. See `scripts/rebuild.sh` and the CoreDevice installation procedure.
- Authorize suggestion previews only from the completed batch scan’s actual UID set, behind the sensitive gate. Index counts cannot identify unchecked or corrupt rows. Keep metadata/result membership intact. Wait for semantic completion and settled non-deferred indexing work before generating new evidence; deferred native retries are not active full indexing. Restore validated saved rows independently of that generation gate. Publish first safe metadata and concept previews before network-backed place names. Store exact scanned membership grouped by volume and restrict it to current inventory without another whole-library hash set. See `MLSemanticSearchEngine.swift`, `SmartSearchDiscoveryScheduler.swift`, and `SmartSearchDiscoveryModel.swift`.
- Use an explicit pending-work barrier when testing superseded timeline projections. `Task.yield()` does not establish request order; the alleged stale request can enter last and correctly replace the newer test variable. Keep the hook Debug-only and preserve all stale-result assertions. See `TimelineSearchProjection.swift` and `TimelineSearchProjectionTests.swift`.
- Keep the distinction between a reproduced old defect and a new runtime regression. The pre-audit thumbnail starter can restart after metadata changes; the photo-ID-only preview task can miss feed replacement; selection can suppress completed semantic publication. These independently reproduced defects have targeted repairs and tests; preserve their limited causal claim. Do not claim they explain the Build 82 incident without a causal comparison. See `MobileLibraryModel.swift`, `MobileSearchLandingScreen.swift`, and `MLSmartSearchLifecycle.swift`.
- Admit automatic iOS suggestion work only after existing initial library, visible-content, thumbnail, and refresh work settles. Include that readiness in the host update identity. Cancel superseded content work instead of finishing an obsolete full scan before starting another. Evict exact evidence under memory pressure or disabled visual search, and reject late cache publication. See `SmartSearchDiscoveryScheduler.swift` and `EncryptedMemoriesMobileApp.swift`.
- Restore completed suggestions when the complete local inventory and favorites are available and the stable content fingerprint matches. Do not wait for server validation or thumbnails. Process-local revisions and Swift hashes cannot identify a relaunch. Bind encrypted persistence to the verified active model and index generation; reject retired read and write leases and remove the file in journaled model cleanup. Require every sensitive prompt and bump the payload version for incompatible policy changes. See `MLSearchSuggestionCache.swift`, `MLSmartSearchLifecycle.swift`, and `SmartSearchDiscoveryPersistence.swift`.
- Include model activation in suggestion-cache readiness independently of index coverage. A nil lease before activation must be retried when `.waiting` still has empty coverage. Retry failed writes without recomputing finished rows; retire pending persistence with evicted evidence, and reacquire both evidence and authority after a stale lease. A ready-only fake cache misses this cold-start failure. See `SmartSearchDiscoveryScheduler.swift` and `SmartSearchDiscoverySchedulerTests.swift`.
- Let map clusters resolve the same platform grid profile as the library. An explicit sparse-collection profile changes gaps and zoom density despite sharing the renderer. Keep cluster order, selection and viewer context separate from grid metrics. See `MainView.swift` and `MobileMapClusterSeriesScreen.swift`.
- Keep canonical timeline snapshots chronological. Reverse only the cached collection presentation, and give the grid data source and viewer the same order. Reverse map identities before paging so the first page contains the newest photos. Recompute presentation on route changes even when photo content is identical. Legacy `.oldest` viewport placement means the first/top edge of the supplied array, which can contain the newest photo. Preserve zoom column phase: leading empty slots can retain the photo under the gesture. See `TimelineView.swift`, `TimelineViewModel.swift`, `TimelineSnapshotReconciler.swift`, `MobileMapScreen.swift`, and `UIKitTimelineGridHostPinch.swift`.
- Retain one nonempty startup thumbnail crawl per load generation. Reset its owner during retry, replacement load, and teardown. Empty inventories must not consume the start. Later arrivals use the existing incremental coordinator. See `MobileLibraryModel.swift` and `MobileThumbnailStartupTests.swift`.
- Await source admission before clearing a bound thumbnail cache. Visible publication can precede asynchronous primary-inventory admission. A raw UID override cannot replace the feed's authorized source scopes. Keep additional-source photos when the primary inventory is empty, and preserve disabled prefetch. Test with the real source runtime and disk downloads; an unbound feed and retained decoded images missed stale restored or removed photos. See `MobileLibraryModel.clearCache`, `LibrarySourceAnalysisRuntime`, `ThumbnailFeedCore.clearCacheAndRestartPrefetch`, and `MobileThumbnailStartupTests.swift`.
- Key search preview loading by photo UID and authenticated feed identity. Reject cancelled results after the await. A stable UID alone misses feed arrival or replacement. See `MobileSearchLandingScreen.swift` and `MobileSearchThumbnailTests.swift`.
- Wake the existing ML loop after selection only for complete coverage from the current activation and library generations. Preserve shutdown, pending-operation and failure-backoff guards. Selection ownership can suppress the final ready publication. See `MLSmartSearchLifecycle.swift` and `MLSmartSearchLifecycleTests.swift`.
- Preserve photo-volume bootstrap before timeline enumeration for a new Proton account that never opened Drive. Coalesce concurrent creation requests. An empty-array fixture does not exercise this account state. See `PhotosVolumeBootstrapService.swift`, `DriveSDKBridge.resolvePhotosRoot`, and `PhotosVolumeBootstrapServiceTests.swift`.
- Match each SDK callback box to its request's actual return type when upgrading to SDK 0.28 or later. Upstream registry lookups reject `Int` boxes for `Void` timeline, album, node-result, node-UID, device, thumbnail and event enumerations, so every yield is silently dropped. Preserve `Int` for controller/progress/stream callbacks and `[String]` for duplicate lookup. See `VendorPatches/sdk-swift`, `Vendor/sdk-swift/Tests/EnumerationCallbackTests.swift`, and the `ProjectHygieneTests` Void-box guard.
- Give `HttpClientProtocol.requestSmallUpload` its own route in `SDKHttpClient.swift`. `requestUploadToStorage` omits session auth, and `requestDriveApi` relabels a body without Content-Type as JSON, which corrupts a multipart upload. Send the body unchanged with session auth on the trusted API host, never resend after a transport error, 429 or 5xx, and keep only the existing one-shot refresh after a 401. Never log or derive the `metadata` side channel.
- Coordinate SDK restoration before running `scripts/update-proton-sdk.sh`. It deletes canonical derived-data, SwiftPM and Xcode package caches without acquiring the build lock. Never run it while another build owns that root. After the SDK upgrade reaches main, keep all builds on the canonical root; reuse a verified pinned vendor checkout when available instead of clearing shared caches.
- Regenerate the versioned vendor patches from a nested checkout with `git diff --unified=0` against the renamed pristine tag, keeping `0001` and `0002` on disjoint or sequential hunks. The updater applies each zero-context patch with `--unidiff-zero`, so a hunk written against the wrong base fails before the checkout changes. See `scripts/update-proton-sdk.sh`.
- Export `DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer` before any direct `xcrun swift test`, `swift-format` or `scripts/lint-swift.sh` call. `xcode-select` points at CommandLineTools on the build machine: `xcrun` then runs the CommandLineTools toolchain and SwiftLint aborts while loading `sourcekitdInProc`. The repository gate scripts export the variable themselves.
- Pass file lists to `scripts/check-swift-format.sh` and `scripts/lint-swift.sh` as separate shell arguments. An unquoted zsh variable does not word-split, so one argument with spaces matches no file and both scripts report "No ... files" with exit 0.
- Register `.search` runtime activity only for a nonempty foreground search query, not for the idle Search tab. The activity gate pauses both automatic ML indexing and suggestion generation; `iOSApp/EncryptedMemoriesMobileApp.swift` previously registered it while the user only viewed the empty suggestion landing.
- Give deferred native-index work a future retry time and let untouched queued assets take the next quantum. A `sourceNotResident` deferral with an immediate retry monopolized the two-asset quantum on Firestarter, leaving 118 later assets pending and the rounded 100% index in `.waiting`; see `MLIndexRunner.runDerivedPass` and `AppleVisionTextPipelineExecutor`.
- Do not make suggestion generation depend on aggregate `.ready` merely to limit load. That new gate in the SDK-0.29 persistence port regressed previously working generation: Firestarter's deferred native `sourceNotResident` work keeps the aggregate in `.waiting`. Build 90 drained 118 untouched assets but left 55 deferred assets and an empty Search landing. Distinguish active heavy work from deferred retries, preserve thumbnail-download priority and exact sensitive-preview evidence, and diagnose the original cache-restore failure separately. A rounded 100% Settings indicator does not prove `.ready`. See `SmartSearchDiscoveryScheduler.permitsAutomaticGeneration` and `SmartSearchDiscoveryModel.visualIndexReady`.
- Restore persisted locations before validating suggestion content, independently of opening Map. Mobile startup previously supplied empty coordinates until Map opened, although the saved suggestion fingerprint included locations; unchanged libraries could therefore fail restoration. Reuse the existing `PhotoLocationStore` load within the joined account load task in `MobileLibraryModel`; do not start location crawling or geocoding to restore suggestions.
- Canonicalize suggestion fingerprints by stable asset identity, not timeline presentation order. Cached and refreshed timelines can order equal-date assets differently; this must not invalidate a completed collection. Keep actual item, favorite, coordinate, calendar, locale and policy changes invalidating. See `SmartSearchDiscoveryPersistence.fingerprint` and its ordering/deletion regression test.
- Validate persisted preview evidence against the current visual-search policy, not `settledVisualAvailability`. That optional value records whether visual stages ran, not whether metadata-only previews need ML. Conflating these meanings either rejects metadata caches or changes structured-selection semantics. See `SmartSearchDiscoveryPersistence.hasCompleteEvidence`, `SmartSearchDiscoveryModel.settle`, and scheduler/availability tests.
- Reuse saved suggestion evidence across metadata changes only when asset membership is unchanged. An authenticated index identity does not identify the selected suggestion inventory; otherwise a larger scope can inherit a smaller scope's completed scan. `SmartSearchDiscoveryPersistence.assetFingerprint` fences this reuse; exact full-content restoration remains sufficient for older payloads.
- Revalidate a suggestion cache read after asynchronous decoding, not only when writing. An index mutation can retire the lifecycle lease during decoding without changing the host's presentation key. `MLSearchSuggestionCacheAccess.isCurrent` and `SmartSearchDiscoveryScheduler.prepareCacheIfNeeded` fence publication; `searchSuggestionEvidence` also rejects an inventory revision change during its batch.
- Require authoritative inventory for a new suggestion-evidence batch. Equal transient `.hydrating` snapshots are not proof of an empty library; accepting them can persist empty evidence as completed. The cache-restore path is separate and can use a complete local timeline after its encrypted account/model/content checks. See `MLSmartSearchLifecycle.searchSuggestionEvidence` and its hydrating-inventory regression case.
- Invalidate deleted, changed, or policy-incompatible suggestion rows before resource gates defer regeneration. Background retention must preserve only valid finished rows, not every previous row. See `SmartSearchDiscoveryScheduler.update`, `SmartSearchDiscoveryModel.invalidateRows`, and the blocked-refresh/empty-library regression tests.
- If Xcode package resolution stalls in `KeychainAuthorizationProvider`/`SecItemCopyMatching`, inspect its process sample before retrying. For the public package artifacts in this repository, the documented `-packageAuthorizationProvider netrc` avoids the blocked Keychain lookup without changing Keychain permissions or reading credentials. Evidence: `search-suggestions-handoff/build91-netrc.log` and `/tmp/encryptedmemories-build91-sample.txt`.
- Do not gate suggestion-cache restoration on completion of server validation or first-grid thumbnails. Firestarter Build 91 loaded its local inventory at 08:48:15 but withheld a valid cache until 08:49:06; exact restoration then took 0.96 seconds without a new scan. Hosts must publish cache readiness from the complete local inventory and settled favorites, independently of automatic-generation readiness. Keep the favorites-ready flag observable even when the returned set is empty. See `MobileLibraryModel.allowsSuggestionCacheRestore`, `MainView.suggestionCacheContentReady`, and `search-suggestions-handoff/BUILD91-RUNTIME.md`.
- Exclude learned playback duration from suggestion identity and row invalidation. `TimelineMetadataStore` preserves known `durationSeconds` across server rows that omit it; Firestarter has 1,995 such rows. Serializing the whole `PhotoItem` made the local start inventory differ from the same server inventory, although discovery never reads duration. `SmartSearchDiscoveryPersistence.suggestionItem` retains all other fields; the real SQLite round-trip regression test must stay green. Build 93 restored the original unchanged cache with `exactContent=true`; the user confirmed immediate rows and previews at Search entry. See `search-suggestions-handoff/BUILD93-RUNTIME.md` for timing limits.
- Distinguish an unavailable model or failed index from active indexing. A native store error can leave semantic phase `.indexing` while aggregate `indexingState` is `.failed`. Permit only local metadata when indexing cannot progress; keep full indexing and thumbnail work ahead of suggestions. This partial pass must not scan embeddings, geocode, persist over a completed collection, or consume the later full-curation wakeup. With visual search enabled it must show no unchecked previews. See `MLSmartSearchState.swift`, `SmartSearchDiscoveryScheduler.swift`, and the blocked-index recovery tests.
- Treat failed favorite loading as unknown, not as a successfully empty set. `DriveSDKBridge.favoriteUIDs()` uses the server photos endpoint; failure has no local authoritative fallback. Both hosts must withhold content readiness, and the shared scheduler must cancel current work and block restoration/generation until content is known. Keep the existing cache intact; a successful empty response is valid. Retry unknown iOS favorites through existing connectivity/library refresh signals, with one task owner, the mutation journal, and account/load-generation guards. A startup-only read otherwise leaves suggestions blocked after reconnection. The journal must also cover mutations already in flight when a retry starts: those can begin while the failed load is marked settled, so an older retry response can otherwise erase a successful heart action. See `MobileLibraryModel.loadFavoritesIfNeeded`, `MainView.loadAlbums`, and the unknown-content scheduler and hosted recovery tests.
- Refresh only the macOS toolbar title's view identity when its text changes. The native toolbar retained the initial title's measurement and accessibility label, so longer route titles overlapped the sidebar toggle. Removing `fixedSize` only replaced the overlap with truncation. Keep the native toolbar item and sidebar ownership stable; see `MainView.toolbarContent`.
- Use canonical fixed-gap geometry and the bounded release camera during a live window-width drag. Scaling captured viewport rectangles around the center or bottom creates temporary empty bands, especially for short collections. Query visible rows with the fixed level and phase: the initial overscan cannot cover an extreme width shrink. Do not loop over `slotRect`; it has no section-layout cache. Preserve height-only counter-scroll and release anchoring; see `MetalGridCoordinator.resizePresentationSlots` and `SquareTileGridEngine`.
